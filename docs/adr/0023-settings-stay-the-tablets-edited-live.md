# Machine and Tablet Settings stay the tablet's, and the management interface edits them live

The management interface edits a Machine's Machine Settings and its Tablet's Tablet Settings, which Decaid lets a plugin write through its API, as Streamline's settings page does. Decaid and the Machine stay the source of truth for them, unlike the Library (ADR-0003). A Settings Edit is a one-off write the plugin makes with the calls Streamline makes, and the setting is then whatever the tablet reports. Nothing holds what a setting should be, and nothing puts back a change made on the tablet afterwards: the latest change stands, whichever side made it. An edit is made only while a Tablet's connection holds the Machine, to that Tablet, and is never queued.

## Considered Options

- **Managed settings, as the Library is.** The server would hold each setting and write it back whenever a tablet drifts from it. Rejected: it fights a barista's change made on the tablet, and Decaid resets some settings itself on every reconnect (below), so the server would rewrite them each time. The deferred shared machine settings, one Machine's settings copied to others, may revisit this.
- **A queue.** An edit made while the Machine is offline would wait for its next connection. Rejected: a change landing hours later, over a change a barista made meanwhile, surprises both, and settings are not Library items with ADR-0020's per-field rules to decide between them.

## Consequences

- **Not everything reported is editable.** `GET /machine/settings` also reports the steam flow, the hot water flow and the flush flow, temperature and time, which are the Workflow's: Decaid writes the Workflow's back to the Machine on every reconnect (`_setDe1DefaultsFor` in `decaid:lib/src/controllers/de1_controller.defaults.dart`), and a Loaded Recipe holds them (ADR-0022). The tank temperature is set by every profile Decaid sends the Machine, and the USB charger by the Tablet's charging mode (`BatteryController` in `decaid:lib/src/controllers/battery_controller.dart`), which is editable instead. All of these are shown, read-only, with what sets them.
- **Some edits last only until the Machine reconnects.** Decaid sets the fan threshold to its maximum and the refill kit to automatic each time it connects to the Machine (`_setDe1DefaultsFor`, and `UnifiedDe1.onConnect` in `decaid:lib/src/models/device/impl/de1/unified_de1/unified_de1.dart`). Both stay editable, and the management interface says so. Decent Sync does not write them back: it accepts the gap until Decaid remembers them (decentespresso/decaid#1027). The water refill threshold, which Decaid can set but not report, is left out until Decaid reports it (decentespresso/decaid#1028).
- **The plugin guards each edit.** Each edit carries the values the page showed, and the plugin refuses a field that changed since. It refuses Machine Settings edits while the Machine is running anything, such as a Shot, steam, hot water, a flush or a cleaning cycle, as Decaid does not check.
- **An edit is confirmed by reading it back.** Decaid announces no change of these settings, so after writing, the plugin reads the collection again and reports it with its answer. The edit is applied, applied with the value Decaid set instead (as when it clamps one), refused with Decaid's error, or not confirmed within 60 s. One not confirmed is never sent later.
- **Sensor calibration is set to a value.** Decaid's write corrects the calibration the Machine holds. The management interface sets a value through Decaid's documented read-then-write instead, as Streamline's restore does. Calibrating against a reference instrument, which needs someone at the Machine, stays on the tablet.
- **Across instances.** A Settings Edit is a row in PostgreSQL, announced with `NOTIFY` to the instance holding the Machine's connection, which sends it and records the answer (ADR-0016).
