# The newest versions, and Decent Sync's previous release, enforced at hello

Decent Sync supports the current release of its own plugin and server, and the previous one beside it (ADR-0025), Decaid v0.9.0 and later, and the DYE2 and Streamline builds named below. It supports nothing from the legacy Tcl de1app. v0.9.0 is the first Decaid release that reports every Shot it stores or changes to plugins, imports included. Code for older versions would add paths that nothing exercises, so there is none: what ADR-0025 keeps for the previous release goes once that release is out of its window, and nothing is kept for releases before it. Supporting older Decaid versions, or more releases of the plugin or the server, would take a new decision.

`OLDEST_SUPPORTED_DECAID` (`protocol/src/index.ts`) is the Decaid minimum, always a release rather than a pre-release, and `OLDEST_SUPPORTED_PROTOCOL_VERSION` the oldest protocol version accepted, which is `PROTOCOL_VERSION`. The server enforces both at `hello`. A plugin speaking an older protocol is refused with `plugin_too_old`, as is one more than one wire revision behind the server's (ADR-0025), and a tablet whose Decaid reports an older version (or no release version) with `decaid_too_old`. The reason is recorded on the token's Machine, and the plugin stops until it or Decaid is updated. Decaid's version comes from its `/info` endpoint as `fullVersion`, the tag it was built from plus a build number (`0.9.0+2977`). Every supported Decaid reports it, so `hello` requires it.

We rejected checking the Decaid version in the plugin. The minimum would then move only with a plugin release, and a plugin that refused to connect would leave nothing on the Machine's page. Decaid's manifest has no field for a minimum host version. We also rejected per-record fallbacks for older Decaid layouts. With the minimum enforced, a record missing what every supported Decaid sends is malformed: it is acknowledged and ignored.

## Consequences

- **No compatibility code but ADR-0025's.** No fallbacks for older Decaid record layouts. The plugin and server handle what the other's previous release sends, and send it nothing it can't ignore without the wire revision that brings it, until the wire moves on, and each release migrates the database in place. The protocol stays at version 1: a wire change raises the wire revision instead (ADR-0025).
- **Raising the Decaid minimum.** A release that relies on a newer Decaid raises `OLDEST_SUPPORTED_DECAID`. Once the server is upgraded, it refuses tablets below the new minimum, so the release's upgrade notes name it.
- **de1app.** The plugin skips Decaid's imports from the legacy Tcl app (ids `de1app-*`, ADR-0004). Nothing else handles them.
- **Unfamiliar fields are still accepted.** Validators ignore fields they do not know, and Decaid payloads are stored as sent, so a newer Decaid doesn't break capture.
- **Upstream releases reach every tablet.** Decaid v0.9.0 installs the latest DYE2 and Streamline releases on every tablet within 12 hours (`decaid:lib/src/services/update_check_service.dart`), whatever these minimums say. So a DYE2 or Streamline release that changes what Decent Sync relies on is deployed as it ships, and the minimums follow it.
- **Skins.** Of the skins, Streamline is supported only from streamline-js `main` at `cec5664`. That build adopts a Workflow change made elsewhere rather than pushing its remembered value back (decentespresso/streamline-js#109, ADR-0021); its DYE strip names the recipe it applies in the Workflow's `recipeId` and clears it as Streamline sends a profile or applies a favourite, places recipes by their `stripSlot` (`recipeStripCells` in `streamline-js:src/modules/dye-selection.js`, from `4dbee83`), saves into DYE2's recipes only through DYE2's `record` and `save-recipe` (Save changes and its long-press menu, from `0b48695`), and applies a recipe that holds a grinder or Basket, which v0.2.18's `assertDeclaredFields` refuses (`ea04f83`); it no longer clears the Workflow after a Shot but its note (decentespresso/streamline-js#164), reads a steam time of 0 as no timer, with a heater switch of its own, and has the fixes for streamline-js#143, #147, #148, #149, #153, #155, #156, #157 and #158 (ADR-0021, ADR-0022). Nothing is written for Streamline v0.2.18 or earlier.
- **DYE2.** Decent Sync writes DYE2's storage (ADR-0005), reads the recipe DYE2 and Streamline name in the Workflow, and has DYE2 save each change into it (ADR-0022), so DYE2 is supported only from v0.1.32. From v0.1.26 it names the recipe a Workflow is dialled in to by its record's id there (`context.extras.dye.recipeId`), storing no selection of its own, and clears it on a change of profile (decentespresso/dye2#36); gives recipes opaque ids and a Recipe Slot of their own (`stripSlot`, 1 to 5), keeps any number of recipes, and gave the records with ids `1` to `5` their `stripSlot` once, as it loaded (`migrateRecipeSlots`); saves the Workflow's changes into that recipe when asked (`record`) and makes one of the live Workflow (`save-recipe`); has its dashboard send only its own edits over a fresh read of the Workflow (decentespresso/dye2#31); and fixes decentespresso/dye2#18 to #30, #32 and #33. v0.1.32 takes a recipe naming no bean to mean no bean: applying one clears the Workflow's bean batch, and its records hold explicit nulls for one, which it gave existing records once as it loaded (`ce38984`); holds a recipe on Streamline's strip exactly while it is in a slot, saving one hidden in none (`f88ace0`); keeps a grind setting as typed, a number where it reads as one and otherwise the text (`d858b73`); keeps a recipe applied again on its own profile named (decentespresso/dye2#38, `e5e1120`); and reads the machine's settings at most once a minute as it saves (decentespresso/dye2#40, `ec73c81`), all of which ADR-0022 follows. A Machine with an older DYE2 has no Loaded Recipe, and nothing is written for the behaviour of an earlier DYE2. The recipe, Basket and Tool lists are still written to every sharing tablet, with DYE2 or without it (ADR-0005).
- **Interim: Streamline pinned to `main`.** The Streamline minimum is an untagged `main` commit, `cec5664`, as streamline-js v0.2.18, its latest release, cannot apply a recipe holding a grinder or Basket, and the owner chose not to wait for `ea04f83`, which fixes it, to reach a release. This is interim. Once a tagged Streamline release contains `ea04f83`, the minimum moves to that release. DYE2's minimum is a tagged release, v0.1.32, which contains everything the earlier pin at `main` `2cf631c` did, and from now on minimums are pinned to versioned releases.
- **Older hardware stays supported.** The minimums cover software only. DE1s that report serial `"0"`, and Shots recorded before Decaid v0.7.6 that a supported Decaid still serves, are handled as ADR-0015 describes.
