# The newest versions, and Decent Sync's previous release, enforced at hello

Decent Sync supports the current release of its own plugin and server, and the previous one beside it (ADR-0025), Decaid v0.9.2 and later, and the DYE2 and Streamline releases named below. It supports nothing from the legacy Tcl de1app. v0.9.0 is the first Decaid release that reports every Shot it stores or changes to plugins, imports included, and v0.9.1 the first that keeps the fan threshold and refill kit a Settings Edit writes, writing them again each time it connects to the Machine, where v0.9.0 wrote its own (ADR-0023). v0.9.2 is the first that keeps the flow multiplier one writes the same way, and leaves it as it resets the Machine's settings, where v0.9.1 wrote 1.0; it is also the first that takes a request managing its plugins and Skins only with a token, so that its automatic update checks, once off, can't be turned on through the plugin (ADR-0023). Code for older versions would add paths that nothing exercises, so there is none: what ADR-0025 keeps for the previous release goes once that release is out of its window, and nothing is kept for releases before it. Supporting older Decaid versions, or more releases of the plugin or the server, would take a new decision.

`OLDEST_SUPPORTED_DECAID` (`protocol/src/index.ts`) is the Decaid minimum, always a release rather than a pre-release, and `OLDEST_SUPPORTED_PROTOCOL_VERSION` the oldest protocol version accepted, which is `PROTOCOL_VERSION`. The server enforces both at `hello`. A plugin speaking an older protocol is refused with `plugin_too_old`, as is one more than one wire revision behind the server's (ADR-0025), and a tablet whose Decaid reports an older version (or no release version) with `decaid_too_old`. The reason is recorded on the token's Machine, and the plugin stops until it or Decaid is updated. Decaid's version comes from its `/info` endpoint as `fullVersion`, the tag it was built from plus a build number (`0.9.2+3191`). Every supported Decaid reports it, so `hello` requires it.

We rejected checking the Decaid version in the plugin. The minimum would then move only with a plugin release, and a plugin that refused to connect would leave nothing on the Machine's page. Decaid's manifest has no field for a minimum host version. We also rejected per-record fallbacks for older Decaid layouts. With the minimum enforced, a record missing what every supported Decaid sends is malformed: it is acknowledged and ignored.

## Consequences

- **No compatibility code but ADR-0025's.** No fallbacks for older Decaid record layouts. The plugin and server handle what the other's previous release sends, and send it nothing it can't ignore without the wire revision that brings it, until the wire moves on, and each release migrates the database in place. The protocol stays at version 1: a wire change raises the wire revision instead (ADR-0025).
- **Raising the Decaid minimum.** A release that relies on a newer Decaid raises `OLDEST_SUPPORTED_DECAID`. Once the server is upgraded, it refuses tablets below the new minimum, so the release's upgrade notes name it.
- **de1app.** The plugin skips Decaid's imports from the legacy Tcl app (ids `de1app-*`, ADR-0004). Nothing else handles them.
- **Unfamiliar fields are still accepted.** Validators ignore fields they do not know, and Decaid payloads are stored as sent, so a newer Decaid doesn't break capture.
- **Upstream releases reach every tablet.** Decaid installs the latest DYE2 and Streamline releases on every tablet within 12 hours (`decaid:lib/src/services/update_check_service.dart`), whatever these minimums say, and from v0.9.2 puts the DYE2 it bundles, v0.1.37 in that release, over a lower one as it starts (`shouldReplaceBundledPlugin` in `decaid:lib/src/plugins/plugin_version.dart`). So a DYE2 or Streamline release that changes what Decent Sync relies on is deployed as it ships, and the minimums follow it. Each minimum is a tagged release, never a build of `main`: until v0.2.21, Streamline's was `main` at `cec5664`, as its releases up to v0.2.18 could not apply a recipe holding a grinder or Basket.
