# Only the newest versions, enforced at hello

Decent Sync supports only the current release of its own plugin and server, Decaid v0.9.0 and later, and the DYE2 and Streamline builds named below. It supports nothing from the legacy Tcl de1app. v0.9.0 is the first Decaid release that reports every Shot it stores or changes to plugins, imports included. Code for older versions would add paths that nothing exercises, so a release may change the wire protocol or the database incompatibly, and the database may be recreated (ADR-0016). Supporting earlier releases, of Decaid, the plugin or the server, would take a new decision.

`OLDEST_SUPPORTED_DECAID` (`protocol/src/index.ts`) is the Decaid minimum, always a release rather than a pre-release, and `OLDEST_SUPPORTED_PROTOCOL_VERSION` the oldest protocol version accepted, which is `PROTOCOL_VERSION`. The server enforces both at `hello`. A plugin speaking an older protocol is refused with `plugin_too_old`, and a tablet whose Decaid reports an older version (or no release version) with `decaid_too_old`. The reason is recorded on the token's Machine, and the plugin stops until it or Decaid is updated. Decaid's version comes from its `/info` endpoint as `fullVersion`, the tag it was built from plus a build number (`0.9.0+2977`). Every supported Decaid reports it, so `hello` requires it.

We rejected checking the Decaid version in the plugin. The minimum would then move only with a plugin release, and a plugin that refused to connect would leave nothing on the Machine's page. Decaid's manifest has no field for a minimum host version. We also rejected per-record fallbacks for older Decaid layouts. With the minimum enforced, a record missing what every supported Decaid sends is malformed: it is acknowledged and ignored.

## Consequences

- **No compatibility code.** No fallbacks for older Decaid record layouts, no server handling for messages an older plugin sent, and no upgrade paths for data an earlier release stored. The protocol stays at version 1: a wire change needs only the current plugin and server, so it raises no version, and a plugin from before it simply fails validation.
- **Raising the Decaid minimum.** A release that relies on a newer Decaid raises `OLDEST_SUPPORTED_DECAID`. Once the server is upgraded, it refuses tablets below the new minimum, so the release's upgrade notes name it.
- **de1app.** The plugin skips Decaid's imports from the legacy Tcl app (ids `de1app-*`, ADR-0004). Nothing else handles them.
- **Unfamiliar fields are still accepted.** Validators ignore fields they do not know, and Decaid payloads are stored as sent, so a newer Decaid doesn't break capture.
- **Skins.** Of the skins, Streamline is supported only from streamline-js `main` at `c006dac`. That build adopts a Workflow change made elsewhere rather than pushing its remembered value back (decentespresso/streamline-js#109, ADR-0021), selects in DYE2 the recipe its DYE strip applies (ADR-0022), and has the fixes for streamline-js#143, #147, #148, #149, #153 and #155 (in `98b6b90` and `c646088`). Nothing is written for Streamline v0.2.14 or earlier.
- **DYE2.** Decent Sync writes DYE2's storage (ADR-0005) and reads the recipe DYE2 has selected (ADR-0022), so DYE2 is supported only from DYE2 `main` at `2cf631c`, which selects recipes and records dial-in changes into them, and fixes decentespresso/dye2#18 to #29. A Machine with an older DYE2 has no Loaded Recipe, and nothing is written for the behaviour of DYE2 v0.1.20 or earlier. The recipe, Basket and Tool lists are still written to every sharing tablet, with DYE2 or without it (ADR-0005).
- **Interim: DYE2 and Streamline pinned to `main`.** The DYE2 and Streamline minimums are untagged `main` commits, as the owner chose not to wait for these fixes to reach a versioned release. This is interim. Once a tagged DYE2 release contains `2cf631c`, or a tagged Streamline release contains `c006dac` (or a later pinned commit), that minimum moves to the release, and from then on minimums are pinned to versioned releases.
- **Older hardware stays supported.** The minimums cover software only. DE1s that report serial `"0"`, and Shots recorded before Decaid v0.7.6 that a supported Decaid still serves, are handled as ADR-0015 describes.
