# AI Repo Map

Where things live, and what to read for each kind of task. Each file says what it does in its own header; the topic docs below hold the behaviour.

## Layout

### Root

- `package.json`: the npm workspaces and the commands; `docs/DEVELOPMENT.md` lists them.
- `vitest.config.ts`, `vitest.durations.json`: Vitest's projects, workers and timeouts; the durations shards are dealt by.
- `playwright.config.ts`: the e2e suite's config.
- `Dockerfile`, `docker-compose.yml`: the server image, and the self-hosting stack with PostgreSQL (`npm run db:up` starts only its `db`).
- `UPGRADING.md`: upgrade notes, newest first, under Unreleased until a release.
- `GLOSSARY.md`: the domain's terms.
- `decent-sync.reaplugin/`: the committed plugin bundle and manifest Decaid installs, generated by `plugin/build.mjs`.

### `plugin/`

- `build.mjs`: writes `decent-sync.reaplugin/`; `manifest.json` is its template.
- `src/index.ts`: the plugin's entry point.
- `src/host.ts`, `src/globals.d.ts`: what Decaid's plugin host gives the plugin.
- `src/decaid.ts`: Decaid's local API.
- `src/connection.ts`: the server connection: hello, heartbeats, reconnects, chunks received.
- `src/sender.ts`: one connection's frames, chunked within Decaid's pending outbound limit.
- `src/outbox.ts`: the one outbox every delivery shares.
- `src/kept-deliveries.ts`: Workflow and machine state deliveries kept across unloads.
- `src/storage.ts`: Decaid's plugin storage commands.
- `src/tablet-id.ts`: this tablet's id.
- `src/tablet-notice.ts`: the one notice on the tablet saying why the plugin stopped syncing, and its wording.
- `src/settings.ts`: the plugin's settings.
- `src/local-time.ts`: Decaid's local times placed in UTC.
- `src/shots.ts`: Shot events and paged reconciliation.
- `src/shot-gate.ts`: whether the Machine is pulling a Shot.
- `src/steams.ts`: Steam Record polling.
- `src/machine-events.ts`: Workflow changes and machine state transitions.
- `src/machine-activity.ts`: whether the Machine runs nothing.
- `src/collections.ts`, `src/change-detection.ts`: the collections polled and sent, and whether one changed.
- `src/settings-edits.ts`, `src/sensor-calibration.ts`: Settings Edits carried out.
- `src/software-actions.ts`: Software Actions carried out, and answered after a load Decaid makes by itself.
- `src/library-writes.ts`: the Library writes the server asks for, DYE2's lists included.
- `src/loaded-recipes.ts`, `src/loaded-recipe-rules.ts`: the Loaded Recipe followed both ways.
- `src/dye2.ts`: DYE2's `record` route and socket.
- `src/skins.ts`: the `skin` endpoint Streamline reads, and its push.
- `src/skin-api.ts`, `src/skin-requests.ts`: what the plugin serves a Skin, and asks the server for one.
- `src/reference-copies.ts`: the Reference Shot copies kept on the tablet.
- `src/shot-edits.ts`: a Shot's rating and note written through Decaid.
- `src/live-view.ts`: the Live View's frames and sockets.
- `test/`: module tests, and `built-plugin.test.ts`.

### `protocol/`

- `src/index.ts`: wire types, runtime validators and `WIRE_REVISION`, shared by plugin and server, with `LIBRARY_ITEM_KINDS`.
- `src/chunking.ts`: splitting and reassembling a message too large for one frame.
- `src/settings-fields.ts`: each settings field the management interface shows or edits, with its validation.
- `src/settings-history.ts`: how a Settings History compares values and folds changes.
- `src/software-actions.ts`: Software Actions' kinds, times and wire messages.
- `src/machine-states.ts`: naming a Machine State.
- `src/profile.ts`: a profile as Decaid reads and writes one, its ranges by Machine model and checks, and Decaid's id for it; `src/sha256.ts` the hash that id is of.
- `src/simulation.ts`: the simulation of a profile on a puck, the standard one or a Shot's, and how close it comes to a Shot.
- `src/machine-models.ts`: the models a profile runs on, a DE1 or a Bengle, and each one's figures.
- `src/starting-shapes.ts`: the starting shapes a new Profile's Draft can begin from.
- `src/record-samples.ts`, `src/steam-phases.ts`: samples and phases of Shots and Steam Records.
- `test/`: module tests; `wire-revision.test.ts` needs the release tags.
- `test/fixtures/first-drip-cases.json`: a Shot's time to first drip and whether it is Unfinished, case by case, which other ports of the rule test too.

### `server/`

- `prisma/schema.prisma`, `prisma/migrations/`: the schema and migrations.
- `src/main.ts`: config, migrations and bootstrap.
- `src/app.module.ts`: the Nest modules.
- `src/config.ts`, `src/config.module.ts`: configuration from the environment.
- `src/migrations.ts`: migrating under the migration lock.
- `src/database.ts`: connection timeouts, and the 503 for an unreachable database.
- `src/drain.ts`: stopping without failing a request.
- `src/notifications.ts`: each instance's `LISTEN` connection.
- `src/secrets.ts`: random secrets and their hashes.
- `src/management-interface.ts`: serving the built management interface and naming its build.
- `src/health.controller.ts`: the routing check.
- `src/record-filters.ts`, `src/pagination.ts`: list filters and paging shared by Shots and Steam Records.
- `src/accounts/`: accounts, sessions, invites, password resets, guards and Scope.
- `src/locations/`: Locations and their time zones.
- `src/machines/`: machine entries, tokens, identity, Pending Machines, Location History, tablets, crediting.
- `src/sync/`: the plugin's WebSocket gateway at `/sync`, identity resolution and each connection's writes.
- `src/library/`: the Library: taking in tablets' reports, edits, each item's history with its Lost Edits (`history.ts`, `history.service.ts`), Recipes, joining, writes due, which Machines a Profile reaches by their model (`profile-reach.ts`), Drafts (`drafts.*`), publishing them and returning to earlier versions (`publishing.service.ts`), and a Machine following one, with its Trial Shots (`draft-following.ts`, what its tablet is due and how following ends; `draft-following.service.ts`, the REST side).
- `src/shots/`, `src/steam-records/`: capture, extraction, Shot Summaries, spec judgements, edits and reads.
- `src/machine-events/`: Workflow and machine state events, Loaded Recipes, dial-in trail and Machine use.
- `src/collections/`: collections, paired devices, the values of plugins' settings as each reader may see them, and Settings History.
- `src/settings-edits/`: Settings Edits.
- `src/software-actions/`: Software Actions, and a Machine's Tablet Software with how each item updates.
- `src/set-aside-deliveries/`: deliveries set aside.
- `src/skin-requests/`: answers to what a plugin asks for a Skin.
- `src/live-view/`: the Live View's stream, leases and relay.
- `src/connected-apps/`: the OAuth authorization server and Connected Apps.
- `src/mcp/`: the MCP endpoint and its tools.
- `test/`: Seam 1 tests, one file per area.
- `test/recipe-steam-switch.test.ts`: a load switching steam, and a Recipe holding "Off" (#616).
- `test/support/`: the test server, simulated tablet, simulated DYE2 and Streamline, Decaid stand-ins, proxies and fixtures.
- `test/support/decaid-plugins.ts`: the simulated tablet's plugin management, `host.localApi` and update state, as Decaid v0.9.3's.
- `test/support/decaid-notices.ts`: the simulated tablet's notification center, `host.notify` and `host.dismissNotification`, as Decaid v0.9.3's.
- `test/latest-release/`: the tests against the latest release, the mixed-versions suite among them.
- `test/fixtures/decaid/`: records Decaid, DYE2 and Streamline produced, by version.
- `test/fixtures/decaid/dye2-v0.1.42/`: DYE2 v0.1.42 and Streamline v0.2.31 on Decaid v0.9.2 with a grind setting of 0: applied, saved by `record` and the editor, and an old recipe repaired; its README says what each file holds.
- `test/fixtures/decaid/profile-ids-v0.9.2/`, `profile-ids-v0.9.3/`: the ids Decaid v0.9.2 and v0.9.3 give every profile they bundle and hand-made cases, which `profileId` is checked against; the first folder's `record.mjs` recorded both.
- `test/fixtures/decaid/notices-v0.9.3/`: what Decaid v0.9.3 does with a plugin's notices, recorded headless by its `record.mjs` with a probe plugin; its README says what each file holds.
- `test/fixtures/decaid/tablet-software-v0.9.3/`: Decaid v0.9.3's plugin management, `host.localApi` and update state, recorded headless by its `record.mjs` with a probe plugin; its README says what each file holds.
- `test/fixtures/decaid/streamline-v0.2.31/`: Streamline v0.2.31 and DYE2 v0.1.42 on Decaid v0.9.2 applying a recipe with steam on and off; its README says what each file holds.

### `web/`

- `src/App.tsx`: the routes.
- `src/auth.tsx`: who is signed in.
- `src/pages/`: one page per route.
- `src/components/`: the pages' parts; `ui/` holds the shadcn/ui components.
- `src/lib/`: pure modules, tested in `test/`; `api.ts` calls the REST API, `build.ts` follows the server's build.
- `src/assets/`, `public/`: the logo drawings and the browser icons.

### Tests, scripts and CI

- `e2e/`: Playwright specs (Seam 2); `e2e/support/` holds their seeding and helpers.
- `scripts/`: repo checks, release packaging, the test PostgreSQL, stale builds, the latest release's build and suite; tests in `scripts/test/`.
- `scripts/readme-images/`: the generator of the README's images in `docs/images/` (`npm run readme-images`), with its sample of recorded Shots.
- `scripts/simulation/`: the simulation's scorecard (`npm run simulation-scorecard`), the read-only puller of an instance's Shots and the scrubber that makes corpus Shots of them.
- `scripts/simulation/corpus/`: scrubbed real Shots the scorecard's test runs on, and the levels its test holds the simulation at on them (`levels.json`).
- `.github/workflows/ci.yml`: CI on pull requests and `main`.
- `.github/workflows/release.yml`: the release on a `vX.Y.Z` tag.
